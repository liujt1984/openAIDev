验证日期：2026-09-25。执行环境：Windows、本机 Node.js 24、微信开发者工具 Stable 2.02.2608070、游客模式模拟器。

- **模拟器页面冒烟**：找拼车、发布、我的行程、家长档案四个主页面，截图已保存。
- **模拟器完整演示接送流程**：林同学家长申请 → 陈同学家长接受并占座 → 家长记录学生已知晓 → 上车 → 到达 → 交接 → AA 账单 → 家长确认金额 → 双方分别记录线下付款 / 收款。

实际演示账单：65 公里 × 0.80 元，过路费 0 元；自家 2 人 + 搭乘学生 1 人。搭乘学生 17.33 元，开车家庭 34.67 元。金额按“分”处理，尾差由开车家庭承担。

模拟器 E2E 完成后已恢复原本的本地演示数据，未发送真实消息、未支付费用。

## 关键测试覆盖

- 待确认申请不占座，最后一个座位只能被一次确认占用。
- 无权用户不能确认申请、伪造上车记录或代替搭乘家长确认账单。
- 公共列表不返回学生档案、联系方式和详细位置，未确认不返回接头编号。
- 同一学生时间冲突时拒绝确认，取消后释放占用。
- 上车前必须记录已告知；不能跳过到达直接记录交接。
- 异常保留座位，只有车主可以记录处理结果并恢复原阶段。
- 关联需求因邀请匹配后，取消可恢复找车；家长已明确关闭的需求不会自动重开。
- 已关闭需求的旧邀请不能接受，失败操作不会留下座位 / 时间占用。
- 未完成交接不能出账单；收费金额由搭乘家长确认，双方独立记录线下结清。
- 无效日期、负费用、座位超额、重复申请和自我申请被拦截。

座位竞争测试在本地串行事务模拟器中执行，验证领域约束；**不是对真实云数据库并发能力的验收**。
