# 第一版需求映射

## 产品边界

家长接送自己孩子时顺路捎带同校学生。驾车与搭乘身份可随行程切换，双方自主确认。没有统一排车、派单或商业车队管理功能。

## 本版取舍

| 已确认需求 | 本版实现 | 后续扩展 |
|---|---|---|
| 家长发布车辆空位 | 双方向、日期时间、区域途经点、座位、精确接送点 | 接受时间范围、地图途经点 |
| 家长发布搭车需求 | 每位孩子单独需求，车主邀请 | 多个费用方式可接受、需求自动关联主动申请 |
| 顺路匹配 | 区域文字筛选、日期方向费用过滤、收藏优先 | 距离和绕路时间计算、历史共同出行优先 |
| 座位与重复预约 | 确认时占座、事务内冲突检查、取消释放 | 用实际行程时段替代固定前后 4 小时规则 |
| 无手机学生 | 家长告知记录、接头编号、可复制纸质确认单内容 | 一键图片 / PDF 确认单、正式离线名单 |
| 临时更改 | 发布后接送时间地点、费用不允许直接改；取消重新发布 | 带版本号的变更提案与重新确认 |
| 接送状态 | 上车、到达、交接分别记录，异常与恢复 | 家长接走双向确认、超时提醒 |
| 费用 | 免费、固定金额、同区间 AA、账单及双向线下结清 | 账单争议 / 修订、可选在线支付、分段 AA |
| 信任关系 | 收藏、屏蔽、举报入库，真实显示未审核 | 身份资料审核后台、手机号验证、举报处置 |
| 通知 | 进入页面加载最新进度、历史操作时间线 | 微信订阅通知、未读消息、失败重试 |
| 隐私 | 公开数据裁剪、服务端权限、云集合客户端禁读写 | 信息授权、保留期限、删除与后台审计 |

## 重要交互约定

- 邀请和申请不占座；只有确认成功才占座。
- 学生是申请的主体，每次一个孩子占一个座位。第一版发布车辆最多 7 座，包含驾驶人和自家乘员。
- 原档案的电话或车辆更新，不自动改变已发布行程中的约定信息。
- 上车后不可简单取消；登记异常并记录处理结果，继续完成交接。
- 返校的“已交接”必须填写实际下车情况，不等于学校确认入校。
- 免费行程无需费用确认；收费行程全部需要搭乘家长确认账单。
- 复制名单到其他应用后，小程序无法再控制副本权限，应只用于本次接送。

## 下一阶段顺序

1. 用真实 AppID / 云环境做双手机联调，验证事务与查询索引。
2. 补家长、车辆审核后台和手机号验证。
3. 接入关键节点订阅通知、取消提醒和未读动态。
4. 补隐私授权与数据删除流程、账单争议修订。
5. 真实家庭小范围试用后再决定地图、图片确认单与在线支付。
